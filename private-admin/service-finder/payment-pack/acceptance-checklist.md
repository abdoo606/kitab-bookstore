# قائمة القبول والتسليم — Acceptance & Handover Checklist
تُستخدم عند قبول عميل فعلي لأي عرض. لا خطوة مدفوعة دون توثيقها هنا.

## قبل بدء العمل المدفوع
- [ ] ردّ العميل الأصلي قُرئ كاملاً (الجهة، الشخص، النطاق المطلوب، أي شروط جديدة).
- [ ] الـSOW مُلئ ووافق عليه العميل كتابياً (بريد صريح أو توقيع): نطاق، مخرجات، جدول، سعر، جولات تعديل، مستثنيات.
- [ ] المحتوى والهوية والأصول المطلوبة من العميل مستلمة أو مؤجلة بتاريخ مكتوب.
- [ ] فاتورة المرحلة 1 صادرة + تعليمات دفع بنفس رقم الفاتورة.
- [ ] عنوان TRC20 من المستخدم نفسه مدخل في التعليقات (لا عنوان من أي مصدر آخر).
- [ ] تحويل اختبار صغير مستلم ومؤكد (TXID + مستكشف TRON) — لأول تعامل.
- [ ] بقية المرحلة 1 مؤكدة على الشبكة. البدء يُوثَّق بتاريخ.

## أثناء العمل
- [ ] البناء في مجلد builds/<slug> مع README (نطاق، تشغيل، حدود، بيانات وهمية معلّمة إن وجدت).
- [ ] فحص: JS بلا أخطاء، كل الصفحات/الملفات 200 محلياً، روابط داخلية سليمة، أساسيات وصول.
- [ ] معاينة للمراجعة ضمن جولتي التعديل المتفق عليهما فقط؛ أي توسيع نطاق = سعر مكتوب جديد قبل التنفيذ.

## القبول والتسليم النهائي
- [ ] ملاحظات العميل الموحدة عولجت ضمن الجولات المشمولة.
- [ ] فاتورة المرحلة الأخيرة صادرة ومؤكدة على الشبكة.
- [ ] حزمة المصدر الإنتاجية النهائية سلُّمت (ZIP/Repo) + تعليمات تشغيل ونشر.
- [ ] ما ليس مشمولاً (استضافة/تراخيص/صيانة) مذكور كتابياً في رسالة التسليم.
- [ ] سُجّل كل شيء: أرقام الفواتير، TXIDs، التواريخ، روابط التسليم — في تقرير الجولة وتعليق درايف.

## علامات إيقاف فورية
طلب «رسوم تحرير/تفعيل»، شراء أدوات كشرط دفع، دفع خارج قناة طلب رسمية (مثلاً خارج Upwork لطلب Upwork)، ضغط لتسليم النهائي قبل تأكيد الدفعة، أو طلب بيانات محفظة سرية.
